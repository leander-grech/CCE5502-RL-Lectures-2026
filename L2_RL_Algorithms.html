Part 1

Planning by dynamic programming

Assume we know $\mathcal{P}$ and $\mathcal{R}$. How do we find the best policy?

How to improve a policy

Given a policy $\pi$:

  1. Evaluate it: compute $v_\pi$
  2. Improve it: act greedily w.r.t. $v_\pi$ → $\pi' \geq \pi$

Repeat. For finite MDPs this always converges to $\pi_*$.

Generalised policy iteration (GPI): almost every RL algorithm is some mix of evaluation and improvement — they differ in how (and how thoroughly) they do each.

Iterative policy evaluation

Problem: evaluate a given policy $\pi$.   Solution: apply the Bellman expectation equation as an update rule, over and over:

$\est{v_{k+1}(s)} = \sum_{a} \pi(a|s) \left( \rew{\mathcal{R}^a_s} + \gamma \sum_{s'} \mathcal{P}^a_{ss'}\, \nxt{v_k(s')} \right) \qquad \est{\mathbf{v}_{k+1}} = \rew{\mathcal{R}^\pi} + \gamma \mathcal{P}^\pi \nxt{\mathbf{v}_k}$
  • Start from $v_0 = 0$; iterate $v_0 \to v_1 \to v_2 \to \dots \to v_\pi$
  • Synchronous: every state is updated in every sweep, from the previous sweep's numbers
  • Needs the model $\mathcal{P}, \mathcal{R}$ → this is planning
A state's new value = the average (over what π does and what the world does) of reward + γ × the neighbour's old value. Repeat until the numbers stop changing. Each sweep, news about rewards travels one step further.

Worked example (4×4 grid, −1 per move, random policy, γ = 1)
Sweep 1: every cell $= -1$.   Sweep 2: the cell next to an exit $= -1 + \tfrac14(0 - 1 - 1 - 1) = -1.75$, cells further away $= -1 + \tfrac14(-4) = -2$.
Exactly what you'll see on the next slide.

Evaluating the random policy — and improving it

Reward −1 per step, $\gamma = 1$, grey = terminal.

  • Evaluate: 1 sweep
    $v_{k+1}(s) = \sum_a \pi(a|s)\,\big(r + \gamma v_k(s')\big)$
  • Evaluate ⟳ repeat until converged
    $v_k \to v_\pi \;\;(\max_s |\Delta v| < 10^{-3})$
  • Improve π
    point each arrow at the best next state under the current $v$ (ties split)
  • Reset  $v = 0$, π uniform random

Try: 1 sweep a few times, then Improve π after $k = 1, 2, 3$.

Greedy w.r.t. an unfinished $v_k$ is often already optimal!

Policy improvement

Act greedily with respect to $q_\pi$:   $\pi'(s) = \arg\max_{a} q_\pi(s,a)$

In each state, look one step ahead and switch to the action with the highest $q_\pi$. E.g. $q(s,{\uparrow}) = -3,\ q(s,{\rightarrow}) = -2,\ q(s,{\downarrow}) = -5 \Rightarrow$ choose →. It can never hurt: you only switch if the new action is at least as good even if you go back to the old policy afterwards.

Formally, one greedy step is at least as good as following π:

$q_\pi(s, \pi'(s)) = \max_a q_\pi(s,a) \;\geq\; q_\pi(s, \pi(s)) = v_\pi(s)$

…and unrolling it shows $v_{\pi'}(s) \geq v_\pi(s)$ for all $s$ (policy improvement theorem).

If improvement stops ($=$ instead of $\geq$): $\;v_\pi(s) = \max_a q_\pi(s,a)$ — that is the Bellman optimality equation, so $v_\pi = v_*$ and $\pi$ is optimal.

Policy iteration and value iteration, live

Value iteration vs policy iteration

Value iteration: $\quad \est{v_{k+1}(s)} = \max_a \left( \rew{\mathcal{R}^a_s} + \gamma \sum_{s'} \mathcal{P}^a_{ss'}\, \nxt{v_k(s')} \right)$
Value iteration = policy iteration where evaluation is cut short to one sweep, and the greedy step is folded in (the max). Don't wait for exact values: improve straight away.

Two big problems with DP: (1) needs the model $\mathcal{P}, \mathcal{R}$; (2) sweeps the entire state space. Real problems: unknown model, astronomically many states → learn from sampled experience.

Part 2

Learning from experience

No model. The agent only sees $S_t, A_t, R_{t+1}, S_{t+1}, \dots$ — can it still estimate values?

Going model-free: use $Q$, not $V$

Greedy improvement over $V(s)$ needs a model

$\pi'(s) = \arg\max_a \Big( \underbrace{\rew{\mathcal{R}^a_s} + \gamma\sum_{s'} \mathcal{P}^a_{ss'}}_{\text{model!}} \nxt{V(s')} \Big)$

Greedy improvement over $Q(s,a)$ is model-free

$\pi'(s) = \arg\max_a Q(s,a)$

The dynamics are learned implicitly inside $Q$.

$V(s)$ says how good a place is. To pick a move from it, you must know where each move leads: that's the model. $Q(s,a)$ scores the move itself, so you just take the highest. No model needed.

Second problem: if we always act greedily, we only ever see the actions we think are best. We must also explore.

Exploration vs exploitation

ε-greedy exploration

  • With probability $1 - \varepsilon$: exploit, take the action with the highest $Q$
  • With probability $\varepsilon$: explore, pick uniformly at random among all $m$ actions
The random pick can also land on the best action, so it gets $1 - \varepsilon + \tfrac{\varepsilon}{m}$; every other action gets $\tfrac{\varepsilon}{m}$. Nothing is ever ruled out, so every action keeps being tried.

Example: $m = 4$, $\varepsilon = 0.2$

Part 3

Monte-Carlo and TD learning

Estimate $v_\pi$ from sampled episodes: wait for the real return (MC), or bootstrap from the next estimate (TD).

Monte-Carlo learning

estimate being updatedreal experience (R, G)estimate of the next statetargeterror δ
  • Learn directly from complete episodes of experience — no model
  • Simplest possible idea: value = mean return
  • No bootstrapping; only works for episodic tasks (must terminate)

Estimate $v_\pi(s) = \mathbb{E}[G_t \mid S_t = s]$ by averaging the returns actually seen. After each episode:

$\est{V(S_t)} \leftarrow \est{V(S_t)} + \alpha\, \big(\, \underbrace{\rew{G_t}}_{\tgt{\text{target}}} - \est{V(S_t)} \big)$

MC target = the return that actually happened in this episode.

The pattern behind every update today:   new estimate = old estimate + α × (target − old estimate).
(target − estimate) is the error; α is how far we move towards the target. α = 1/n gives the exact running average (Lecture 1); a constant α weights recent episodes more.

Temporal-Difference learning

  • Learn from incomplete episodes — update after every step
  • Works in continuing (non-terminating) tasks
  • Bootstraps: updates a guess towards a guess
$\est{V(S_t)} \leftarrow \est{V(S_t)} + \alpha\, \big(\, \underbrace{\rew{R_{t+1}} + \gamma \nxt{V(S_{t+1})}}_{\tgt{\text{TD target}}} - \est{V(S_t)} \big)$
Same pattern as MC, different target: one real step + my current guess for the rest. The TD error $\err{\delta_t} = \rew{R_{t+1}} + \gamma \nxt{V(S_{t+1})} - \est{V(S_t)}$ is the surprise: positive → better than expected, so raise $\est{V(S_t)}$.

🚗 If another car nearly crashes into you, you can update "that was dangerous" immediately — no need to actually crash (end the episode) first.

Part 4

Model-free control

Put TD inside the GPI loop: learn $Q(s,a)$, act ε-greedily, improve every step.

SARSA: on-policy TD control

$\est{Q(S,A)} \leftarrow \est{Q(S,A)} + \alpha \big( \rew{R} + \gamma\, \nxt{Q(S', A')} - \est{Q(S,A)} \big)$
  • Uses the tuple $(\est{S}, \est{A}, \rew{R}, \nxt{S'}, \nxt{A'})$ — hence the name
  • $\nxt{A'}$ is the next action: the one the agent will actually take (ε-greedy)
  • Every time-step: evaluate (SARSA update, $Q \approx q_\pi$) and improve (ε-greedy on the new $Q$)
The TD update from before, now for $Q$. Target = reward + value of the action I'm really going to take next, exploration included.

SARSA, one update at a time

Off-policy learning

Evaluate a target policy $\pi$ while following a different behaviour policy $\mu$.

On-policy

“Learn on the job”. Learn about $\pi$ from experience sampled from $\pi$. Can't reuse old data.

Off-policy

“Look over someone's shoulder”. Learn about $\pi$ from experience sampled from $\mu$.

Two roles: the behaviour policy decides what the agent actually does (e.g. ε-greedy, explores). The target policy is the one we want to learn about (e.g. greedy). On-policy: they are the same. Off-policy: they differ.

Why bother?

  • Learn from observing humans or other agents
  • Re-use experience generated by old policies $\pi_1, \dots, \pi_{t-1}$ ← the replay buffer in DQN
  • Learn about the optimal policy while following an exploratory one

Q-learning: off-policy TD control

  • Behaviour policy $\mu$: ε-greedy w.r.t. $Q$ (explores)
  • Target policy $\pi$: greedy w.r.t. $Q$, so the next state is worth its best Q-value, $\nxt{\max_{a'} Q(S', a')}$
Target = reward + value of the best next action, whatever I actually do next. It learns about acting greedily while behaving ε-greedily.
$\est{Q(S,A)} \leftarrow \est{Q(S,A)} + \alpha \big( \rew{R} + \gamma\, \nxt{\max_{a'} Q(S', a')} - \est{Q(S,A)} \big)$

Theorem: Q-learning control converges to the optimal action-value function, $Q(s,a) \to q_*(s,a)$ (tabular, all pairs visited infinitely often).

🧠 Quick check: SARSA vs Q-learning

1
Which algorithm learns the value of the policy it is executing, exploration included?
SARSA (on-policy): its target uses the action it will really take.
2
Why can Q-learning learn from a replay buffer of old experience, but SARSA can't (directly)?
Q-learning's target uses the best next action, not the one the old policy took, so it doesn't matter who generated the data (off-policy).
3
How big is a tabular Q-table for CartPole?
Infinite: the state is continuous → we need function approximation (next: DQN).
Part 5

Deep Q-Networks

Replace the table with a neural network.

Q-learning with function approximation

Approximate $Q$ with a network with weights $\theta$:  $Q(s, a; \theta) \approx q_*(s, a)$, and turn the Q-learning update into a regression problem:

$L(\theta) = \mathbb{E}\Big[ \big( \underbrace{\rew{r} + \gamma \nxt{\max_{a'} Q(s', a'; \theta^-)}}_{\tgt{\text{target } y}} - \est{Q(s, a; \theta)} \big)^2 \Big]$

Table (Q-learning)

Q[s,a] += α·(y − Q[s,a])
overwrites one cell only

Network (DQN)

θ −= η·∇θ (y − Q(s,a;θ))²
nudges all weights, so similar states change too (generalisation)

Ordinary supervised regression, except the "labels" $\tgt{y}$ are made by the network itself from one real step plus its own estimate of the next state. Same target as Q-learning.

The Q-network

Why naive deep Q-learning is unstable

1. Correlated samples

Consecutive transitions are nearly identical. Gradient descent assumes shuffled, independent samples (i.i.d.) → the net over-fits the current region and forgets the rest.

Fix: experience replay buffer

2. Moving targets

The target $y$ depends on $\theta$: every update moves the target — a dog chasing its tail.

Fix: slowly-updated target network $\theta^-$

The “deadly triad” (Sutton & Barto): function approximation + bootstrapping + off-policy learning can diverge. DQN uses all three — replay and target networks are what keep it stable in practice.

DQN machinery: replay buffer + target network

DQN algorithm

# Mnih et al., "Human-level control through deep RL", Nature 2015
initialise Q-network θ, target network θ⁻ ← θ, replay buffer D
for step t = 1 ... T:
    a = random action              with prob. ε      ① explore (ε decays over time)
        argmax_a Q(s, a; θ)        otherwise
    s', r, done = env.step(a);   D.append((s, a, r, s', done))   ② remember
    if t > learning_starts and t % train_freq == 0:
        sample minibatch (s, a, r, s', done) ~ D                  ③ random past experience
        y = r + γ · (1 − done) · max_a' Q(s', a'; θ⁻)             ④ TD target, frozen net
        θ ← θ − η ∇θ (y − Q(s, a; θ))²                            ⑤ regression step
    if t % target_update_interval == 0:  θ⁻ ← θ                ⑥ refresh the target
    s = s' (or env.reset() if episode ended)

Every name in this pseudocode is a Stable-Baselines3 hyperparameter.

CartPole

State $(x, \dot x, \theta, \dot\theta)$ · actions: push left / right · reward +1 per step upright · ends when $|\theta| > 12°$ or $|x| > 2.4$ · truncated at 500.

What is the “linear policy”?

A policy with just 4 numbers $w = (w_1, w_2, w_3, w_4)$:

$\pi_w(s) = \begin{cases} \text{push right} & \text{if } w_1 x + w_2 \dot x + w_3 \theta + w_4 \dot\theta > 0 \\ \text{push left} & \text{otherwise} \end{cases}$
  • Linear: the decision is the sign of a weighted sum of the state — a straight line (hyperplane) splits state space into a “left” half and a “right” half
  • Intuition for a good $w$: pole leaning right ($\theta > 0$) or falling right ($\dot\theta > 0$) → push right to get the cart back under it. So $w_3, w_4 > 0$ and large
  • It is deterministic and has no value function — it is a policy-search method, not Q-learning

How it's trained here: random search (hill climbing)

  1. Start from 4 random weights
  2. Perturb: $w' = w + 0.5\,\varepsilon$, $\;\varepsilon \sim \mathcal{N}(0, I)$
  3. Run 3 episodes with $w'$; score = average length
  4. Keep $w'$ if it scored at least as well as $w$
  5. Repeat until 500

No gradients, no Bellman equation: it only uses the total return of whole episodes (like Monte-Carlo). Works because CartPole is easy and needs only 4 parameters; it does not scale to millions of weights → DQN, policy gradients.

The Gymnasium API

import gymnasium as gym

env = gym.make("CartPole-v1", render_mode="human")
obs, info = env.reset(seed=42)
total = 0
while True:
    action = env.action_space.sample()                # random agent
    obs, reward, terminated, truncated, info = env.step(action)
    total += reward
    if terminated or truncated:
        break
print("return:", total)
env.close()

terminated = reached a terminal state of the MDP (pole fell) → no future value.  truncated = time limit hit → the future still exists, so the target should still bootstrap. Mixing them up is a classic bug.

DQN with Stable-Baselines3

from stable_baselines3 import DQN
from stable_baselines3.common.evaluation import evaluate_policy

env = gym.make("CartPole-v1")                      # no rendering while training!
model = DQN("MlpPolicy", env,
            learning_rate=1e-3,                     # step size of gradient descent
            buffer_size=50_000, batch_size=32,     # replay buffer + minibatch size
            learning_starts=1_000, train_freq=4,  # fill the buffer first; learn every 4 steps

Reading RL training curves honestly

  • Always run several seeds (≥ 3). RL results vary wildly between seeds; one lucky run proves nothing.
  • Plot the mean and spread (min–max or ±std), not a single curve.
  • Training reward ≠ performance: it includes exploration. Evaluate separately with deterministic=True.
  • Watch the agent. High reward with weird behaviour usually means the reward is not measuring what you want.

DQN failure modes you may see

  • “Catastrophic forgetting”: reward reaches 500 then crashes
  • Q-values growing without bound (overestimation from the max)
  • Flat curve for a long time: learning_starts or ε schedule

Beyond value-based RL

Learn the policy directly — the family behind PPO, robotics and LLM fine-tuning.

Value-based vs policy-based

Value-based (DQN)Policy-based (REINFORCE, PPO)
Learns$Q(s,a;\theta)$; policy = argmax$\pi(a|s;\theta)$ directly
Continuous actionshard (argmax over ℝⁿ)natural (output a Gaussian)
Stochastic policiesno (ε-greedy is a hack)yes
Sample efficiencyhigh (replay, off-policy)lower (mostly on-policy)
Stabilitydeadly triadsmoother updates
Value-based: learn a score for every action, then pick the best. Policy-based: learn the behaviour directly, and nudge it towards whatever worked better than usual.

Actor-critic methods combine both: an actor $\pi_\theta$ chooses actions, a critic $V_w$ estimates values to judge them.

Policy gradient: make good actions more likely

$\nabla_\theta J(\theta) = \mathbb{E}_\pi\left[\, \nabla_\theta \log \pi_\theta(A_t | S_t)\; \big(\rew{G_t} - b(S_t)\big) \right]$
Try an action. If the return beat the usual level ($G - b > 0$), make that action more likely; if not, less likely. The baseline $b$ = "usual"; it only reduces noise.

PPO: don't change the policy too much at once

$L^{\text{CLIP}}(\theta) = \mathbb{E}_t\Big[ \min\big( r_t(\theta)\, \hat A_t,\; \operatorname{clip}(r_t(\theta), 1-\varepsilon, 1+\varepsilon)\, \hat A_t \big) \Big], \qquad r_t(\theta) = \frac{\pi_\theta(a_t|s_t)}{\pi_{\theta_\text{old}}(a_t|s_t)}$
$r$ = how much more (or less) likely the new policy makes this action than the old one. Good action ($\hat A > 0$): raise $r$, but the gain stops at $1 + \varepsilon$. Bad action: lower $r$, but only down to $1 - \varepsilon$. Many small, safe steps.

Reward design and reward hacking

The agent optimises exactly what you reward. Famous real case: OpenAI's CoastRunners boat circled forever collecting respawning targets instead of finishing the race.

Summary

Planning (DP)

Model known. Policy / value iteration = Bellman equations as update rules.

Prediction

MC: unbiased, high variance, waits for the end. TD: bootstraps, low variance, online.

Control

SARSA (on-policy, safe) vs Q-learning (off-policy, learns $q_*$).

DQN

Q-learning + neural net + replay buffer + target network.

Policy gradients

Push up log-prob of actions with positive advantage. PPO clips the step.

In practice

Seeds, evaluation, watching the agent, and designing the reward carefully.

The thread through today: estimate ← estimate + α (target − estimate). MC, TD, SARSA, Q-learning and DQN differ only in the target.
